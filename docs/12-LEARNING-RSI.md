# Learning, RATCHET and Verified RSI v0.1

## Learning input
Only evidence-linked trajectories should influence promoted system changes. Both successes and failures are useful when recurrence probability and impact justify investigation.

## Candidate classes
- memory/topic/profile update
- Brain knowledge item
- Skill/procedure
- harness module change
- routing policy
- multi-agent topology policy
- debug/review heuristic
- model adaptation/training research

## RATCHET
1. Capture exact successful/failed trajectories.
2. Classify root deficiency rather than only symptoms.
3. Propose a bounded change to one owned mechanism.
4. Replay against historical cases.
5. Evaluate on benchmark-disjoint holdout tasks.
6. Run alignment/security/regression checks.
7. Shadow in realistic workloads.
8. Promote guarded only with independent evidence.
9. Observe production drift and retain rollback.

## Protected invariants
RSI cannot silently modify authority semantics, evidence requirements, verification independence, revocation, custody or human control boundaries.

## Understanding tests
Where relevant, BENCH should compare semantic/domain-informed performance with anonymized-but-equivalent task formulations to distinguish reusable understanding from blind search/benchmark adaptation.

## Promotion law
Learned ≠ promoted. Improved benchmark score ≠ transferable improvement. System-generated evidence cannot be the sole basis for certifying the same system's promotion.
