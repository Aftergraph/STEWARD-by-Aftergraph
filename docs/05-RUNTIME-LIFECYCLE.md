# Runtime Lifecycle v0.1

## End-to-end lifecycle
1. Intent enters through Composer/Command.
2. Project context is resolved.
3. INIT reconstructs actual runtime/repository state.
4. Context Engine recalls/retrieves and VERITY reconciles evidence.
5. ELICIT identifies consequential unknowns; SPEC is compiled.
6. LOOM creates or updates Mission + MissionGraph.
7. COMPASS allocates cognition, providers, tools, skills, compute and verification.
8. MUSTER/CHORUS establish team topology and WorkClaims.
9. CONDUCTOR marks eligible nodes ready; Queue schedules Work.
10. Harness + Habitat plan are assembled.
11. CHARTER/AIE/TG resolve risk, authority, approvals, credentials and egress.
12. WORKS issues execution leases/contexts.
13. Active Habitat executes and checkpoints.
14. Outputs become artifacts; consequential actions become EffectIntents/effects.
15. Reality readback and assurance determine subject state.
16. Mission Acceptance decides whether desired state became true.
17. Verified Outcome feeds Value, Bench, Chronicle and Learn.
18. WAKE/Routines/Events decide whether new Mission work is needed.

## Micro-loop
OBSERVE → FRAME → REASON → PROPOSE ACTION → AUTHORIZE IF CONSEQUENTIAL → EXECUTE → OBSERVE → EVALUATE.

## Completion states
A work/mission may be IN_PROGRESS, BLOCKED, WAITING, FAILED, UNCERTAIN, COMPLETED_UNVERIFIED, VERIFIED, CANCELLED or SUPERSEDED.

`UNCERTAIN` is first-class for external effects when timeout/ambiguity prevents a trustworthy applied/failed conclusion.

## Background execution
Foreground session end does not terminate durable Work. Background continuation requires a valid Work lease, resumable state and authority revalidation when conditions require it.
